# SMB 可生产内容资产库设计

**状态：** 已确认（今日建库范围）  
**日期：** 2026-08-07  
**源素材：** `/Volumes/192.168.50.79`（SMB 只读）  
**目标：** 一次完成全 SMB 素材清单、技术索引、指纹、固定抽帧、CTA 四帧图、目录标签、质量标记，并支持增量更新、断点恢复和本地检索；代理仅对生产候选按需生成。

## 1. 决策摘要

首期直接建设完整的可生产基础库。所有受支持视频都会被扫描、探测、计算指纹并生成两类轻量视觉检查图；后续自动剪辑先查询本地资产库，只对选入生产候选集的素材生成代理。

采用现有 Node.js、JSON 和 FFmpeg/ffprobe，不增加数据库、向量库或模型服务。复核后的当前挂载点可见 2,955 个受支持视频，源视频约 447.29 GiB，本机约有 195 GiB 可用空间。全量代理存在写满本机磁盘的风险，因此不属于今日建库范围；JPEG 检查图和索引仍可一次完成。SMB 仅允许读取，所有状态和衍生物写入仓库的 `work/asset-library/`。

## 2. 方案比较

### A. 全量轻量视觉库、代理按需生成（采用）

全量生成元数据、指纹和检查图，生产候选才生成代理。可以完整建库，同时把本机容量留给实际剪辑任务。

### B. 全量代理

后续剪辑最省等待，但 447.29 GiB 原片对应的代理容量无法在 195 GiB 可用空间内安全保证，因此本期不采用。

### C. 数据库和视觉向量库一次到位

查询能力最强，但会显著增加部署、迁移和维护成本。2,955 个视频仍可由单个 JSON 索引快速检索；等目录标签召回准确率被数据证明不足后再增加视觉语义层。

## 3. 范围

首期必须完成：

- 全 SMB 只读递归扫描和稳定文件清单。
- ffprobe 技术元数据和快速内容指纹。
- 每条素材的固定联系表和 CTA 结尾四帧图。
- 从相对路径提取的基础目录语义标签。
- 失败、重复候选、技术低质量和视觉低质量标记。
- 原子落盘、逐文件状态、断点恢复和增量更新。
- 按路径、标签、状态、规格和时长检索。

首期明确不做：

- 不移动、修改、删除或重命名 SMB 文件。
- 不自动删除重复文件。
- 不做人物、商品、动作的视觉 AI 识别。
- 不做向量库、相似镜头检索、Web 管理后台或任务队列。
- 不让低质量启发式自动淘汰素材；只标记并供人工或选镜规则参考。
- 不全量生成代理；仅在素材进入具体生产候选集时复用现有任务流程按需生成。

## 4. 目录和产物

```text
work/asset-library/
├── catalog.json                 # 当前可检索资产库，原子替换
├── manifest.json                # 本次运行、版本和汇总指标
├── runs/<run-id>.json           # 每次运行结果和错误汇总
├── contacts/<asset-id>.jpg      # 固定抽帧联系表
└── cta/<asset-id>.jpg           # 结尾四帧检查图
```

只保留一个权威 `catalog.json`。不同时维护 SQLite、CSV 和 JSON，避免状态漂移。检索命令直接读取 JSON；需要给人工查看时按查询结果临时输出 TSV，不把 TSV 当数据源。

## 5. 资产契约

每个素材记录至少包含：

```json
{
  "id": "sha256(relativePath,sizeBytes,mtimeMs)",
  "sourcePath": "/Volumes/192.168.50.79/.../M3794.MP4",
  "relativePath": "12.20  S5/人脸相关/M3794.MP4",
  "sizeBytes": 12345678,
  "mtimeMs": 1780000000000,
  "durationInSeconds": 12.4,
  "width": 1080,
  "height": 1920,
  "fps": 30,
  "codec": "h264",
  "hasAudio": true,
  "quickFingerprint": "...",
  "tags": ["12.20", "s5", "人脸相关"],
  "duplicateGroup": null,
  "qualityFlags": [],
  "proxyPath": null,
  "contactSheetPath": "contacts/<asset-id>.jpg",
  "ctaSheetPath": "cta/<asset-id>.jpg",
  "state": "complete",
  "error": null
}
```

状态只允许：

```text
discovered | probed | fingerprinted | frames_ready | complete | failed
```

`failed` 同时记录失败阶段，因此续跑只重试缺失或失败的步骤。已经验证合格的文件不重复生成。

## 6. 数据流

```text
SMB 只读遍历
  → 文件清单
  → ffprobe 元数据
  → 全量快速指纹与同尺寸重复分组
  → 目录标签与技术质量标记
  → 固定联系表 + CTA 四帧图
  → 视觉质量标记
  → catalog.json 原子发布
```

每完成一个素材即把进度原子写入运行状态；进程退出、电脑休眠、网络断开或 FFmpeg 单文件失败后，重新运行会从未完成阶段继续。

## 7. 扫描、增量和指纹

接受扩展名：`.mp4`、`.mov`、`.m4v`，不区分大小写。排除 `.accelerate`、`.DS_Store`、`._*`、`Thumbs.db`、`*.lnk`、`$RECYCLE.BIN` 和 `System Volume Information`。

增量判断使用 `relativePath + sizeBytes + mtimeMs`：

- 三者未变：复用元数据和所有已验证衍生物。
- 文件新增或发生变化：生成新 ID，并从探测阶段处理。
- 文件从 SMB 消失：标记 `missing` 于本次运行记录，不立刻删除本机检查图；连续两次扫描仍缺失后才列入人工清理清单。

每个视频都计算快速指纹：小于 2 MiB 读取全文件，否则读取首尾各 1 MiB。同尺寸且指纹相同的文件只标为 `duplicate_candidate` 并分配同一 `duplicateGroup`，不自动删除或排除。

## 8. 视觉检查图

检查图由 FFmpeg 直接从 SMB 源视频指定时间点抽取并拼接，不先生成代理。JPEG 先写 `.partial.jpg`，验证首尾标记和非零大小后原子改名。

### 8.1 固定联系表

- 不超过 8 秒：中点 1 帧。
- 8–30 秒：20%、50%、80% 三帧。
- 超过 30 秒：每 10 秒一帧，最多 8 帧。

每帧显示相对路径和时间码，用于快速理解整条素材。

### 8.2 CTA 四帧图

CTA 图专门检查结尾是否仍有主体、是否切入空桌面或无效尾帧。固定取：

- `max(0, duration - 4.0s)`
- `max(0, duration - 3.0s)`
- `max(0, duration - 2.0s)`
- `max(0, duration - 0.25s)`

四帧按时间顺序横向或 2×2 拼接，并烧录时间码。短于 4 秒的素材按 10%、40%、70%、95% 取帧，避免重复同一帧。

## 9. 标签和质量标记

### 9.1 基础目录语义标签

标签仅来自相对路径的目录和文件名，执行小写化、空白归一、常见分隔符拆分和日期保留。首期允许一个短的同义词表，例如：

- `s5素材`、`12.20 s5` → `s5`
- `人脸相关`、`模特`、`使用展示` → 分别保留原标签，不擅自合并含义
- `产品`、`产品展示`、`产品细节` → 保留原标签，并补充上位标签 `产品`

原始路径永远保留，自动标签可以重新生成；人工标签在后续阶段以单独覆盖文件加入，不混入首期。

### 9.2 质量标记

确定性标记包括：

- `probe_failed`：无法读取有效视频流。
- `too_short`：时长小于 1 秒。
- `low_resolution`：旋转校正后的短边小于 720。
- `invalid_fps`：帧率小于 20 或无法解析。
- `duplicate_candidate`：同尺寸且快速指纹相同。
- `mostly_black`：固定抽帧中超过一半帧的平均亮度低于阈值。
- `frozen_tail`：CTA 四帧图对应帧差连续低于阈值。
- `empty_tail_candidate`：结尾亮度或帧差出现明显突变；仅作为人工复核提示，不宣称已识别“空桌面”。

亮度和帧差阈值必须保留为常量校准项。因为它们是启发式，任何视觉标记都不能单独阻止素材被人工选用。

## 10. 检索接口

首期提供一个本地命令：

```bash
node scripts/asset-library.mjs search \
  --tag s5 \
  --state complete \
  --exclude-flag duplicate_candidate \
  --orientation portrait
```

支持字段：关键词（路径和标签）、标签、状态、质量标记、横竖屏、编码、最短/最长时长。默认输出精简表格；`--json` 输出完整记录，供自动剪辑流程直接消费。

不实现查询语言或评分 DSL。自动选镜需要的排序先使用：商品标签匹配 → 场景标签匹配 → 无阻断技术错误 → 分辨率 → 时长。

## 11. 失败处理和恢复

- SMB 根不可读或挂载断开：停止本次运行，不发布不完整的新目录快照。
- 单文件探测、指纹或抽帧失败：记录阶段、退出码和错误文本，继续下一个文件。
- JPEG 校验失败：保留错误记录，删除资格由后续人工清理流程决定；不把 partial 当成缓存命中。
- 进程中断：已通过验证的产物保留；下次从第一个未完成阶段继续。
- catalog 发布：始终先写临时 JSON、重新读取验证，再原子改名。
- SMB 只读证明：运行前后记录源文件数量、总字节和最大修改时间；发现变化只报警，不声称一定由本程序造成。

## 12. 验收标准

首轮全量建库完成必须同时满足：

1. 扫描到的受支持视频全部出现在 `catalog.json`，成功与失败均不丢记录。
2. 每个可解码视频都有元数据和状态；重复候选有组 ID，但 SMB 没有任何删除或修改。
3. 每个成功视频都有快速指纹、有效 JPEG 联系表和 CTA 四帧图。
4. 每条记录都有可追溯的目录标签和明确质量标记数组。
5. 任意中断后重跑只处理缺失步骤；无变化的第二次运行不重新 ffprobe、不重算指纹、不重抽帧。
6. 搜索 `s5` 能返回 S5 相关目录素材；搜索失败或重复状态能准确过滤。
7. 单个损坏文件不会终止整库；SMB 断开不会发布半成品 catalog。
8. 全量建库不生成代理；生产候选仍能调用现有流程按需生成代理。
9. 现有自动剪辑测试和 TypeScript 检查继续通过。

## 13. 实施边界

现有 `scripts/lib/index-assets.mjs` 已覆盖单批次扫描、ffprobe 和快速指纹，`prepare-media.mjs` 保留为生产候选的按需代理流程。实现时应复用并最小扩展这些函数：增加全局库入口、逐文件持久状态、直接源文件抽帧、CTA 图、标签、质量标记和搜索。不要复制一套新的媒体探测代码。

完成基础库后，生产顺序调整为：

```text
SMB 内容资产库
  → 脚本/SKU 查询候选素材
  → 自动选镜与 Remotion 剪辑
  → 成片机器验收和 CTA 四帧图
  → 人工快速确认
  → 批量生产
```

视觉 AI、人工修正标签和向量相似检索只在基础库真实运行后，以召回误差和人工耗时为依据决定是否增加。
