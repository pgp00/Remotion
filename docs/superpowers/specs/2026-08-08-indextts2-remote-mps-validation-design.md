# IndexTTS2 远端 MPS 验证设计

## 目标

在 `fang@192.168.77.2` 的 Apple M4、16GB Mac mini 上验证官方 IndexTTS2 能否通过 Apple MPS 稳定生成自然中文广告口播。本轮只产出测试 WAV 和日志，不生成视频、不修改 Remotion 代码。

## 已确认约束

- 优先目标是降低 Edge TTS 的机器感，改善停顿、重音和语气连贯性。
- 使用 IndexTTS2 官方示例音色，不做自有声纹克隆。
- 30 秒配音允许最多等待 5 分钟。
- 用户已授权在远端安装验证所需的软件和模型。
- 远端没有 Homebrew、`uv` 或可用的 Xcode Command Line Tools；可用磁盘约 410GB。

## 方案

使用官方源码、官方 `uv` 环境和 IndexTTS2 CLI，在独立目录 `~/index-tts-validation/` 中运行。只安装基础推理依赖，跳过 WebUI、DeepSpeed、Flash Attention 和 `torch.compile`。推理必须显式使用 `mps`，不能静默回退到 CPU。

验证按两级进行：先生成约 5 秒短句，确认安装、模型和 MPS 路径；成功后再生成接近 30 秒的中文广告文案。官方示例音频作为音色提示。

## 数据流

1. 下载官方源码和模型到远端隔离目录。
2. CLI 检查模型文件、Python 包和 MPS 可用性。
3. 使用同一官方示例音色分别生成短句和长文案。
4. 保存命令输出、耗时、内存快照和 WAV。
5. 用系统音频工具验证 WAV 可解码、采样率、声道和实际时长。

## 成功标准

- `indextts2 check --device mps` 明确报告 MPS 可用。
- 短句和长文案均生成非空、可完整解码的 WAV。
- 约 30 秒输出的端到端生成时间不超过 300 秒。
- 日志没有 OOM、设备回退、漏字或重复生成的迹象。
- 自然度人工检查覆盖漏字/重复、停顿、重音、语气连贯和机器感；人工主观结论由用户试听确认。

## 失败处理

- 下载中断时复用已下载文件继续，不清空目录。
- MPS OOM 或推理异常只在关闭无关进程后重试一次。
- 第二次仍失败即停止并保存日志，不自动使用 CPU，不安装额外加速栈。
- 远端 16GB 若无法满足阈值，结论是该主机不适合作为 IndexTTS2 worker；不改动视频工作流。

- 自有品牌声纹、商用授权确认和长期常驻服务。
- WebUI、Docker、任务队列、API 服务和自动回退系统。
