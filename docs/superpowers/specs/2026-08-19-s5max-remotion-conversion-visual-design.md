# S5Max 抖音转化型 Remotion 视觉升级设计

> 日期：2026-08-19
>
> 状态：四部分设计已确认，等待用户复核书面规格

## 1. 目标

在不新增视频素材的前提下，使用现有 Remotion 生产链为上谷 S5Max 视频增加一套“证据型精致”视觉包装，优先提升抖音信息流中的首 3 秒理解、观看停留和商品点击意愿。

本设计不承诺爆款，也不把增加特效数量作为目标。视觉升级必须帮助观众更快看清真人动作、产品位置、已展示卖点和下一步操作。

## 2. 已确认约束

- 主要平台：抖音。
- 第一目标：停留与带货转化，不以纯品牌广告质感为第一目标。
- 视频画面：只能使用现有素材，可以重新排序、裁切、放大、停帧和复用不同时间段。
- 音频：允许新增来源清楚、可商用的 BGM 和音效。
- 渲染：继续由 Remotion 一次完成最终编码。
- 依赖：不新增动画库、3D、WebGL 或粒子系统。
- 批量能力：视觉模板必须能被现有批量生产链复用，但首版先验证一条母版。
- 真实性：不伪造前后对比，不用产品摆拍代替“不扯须、不泛红、耐用多年”等效果证明。

## 3. 当前基线

当前生产模板位于 `packages/remotion-video/src/production-video.tsx`，具有以下特征：

- 1080×1920、30 fps；当前 S5Max 样片时长为 23.189 秒。
- 7 句口播各对应一个 `Sequence` 和一个视频素材。
- 每个视频素材均设置 `muted`，声音只有逐句 TTS。
- 已检查当前 7 个代理素材：均只有 H.264 视频流，没有可恢复的源音轨。
- 字幕由 `components/subtitle-layer.tsx` 整句显示，当前为 48 px Arial、统一黑色底框、底部 245 px。
- Props 使用严格字段校验，语音是镜头、字幕和总时长的主时钟。

本设计保留上述时间线、素材代理、TTS、单次渲染和 QC 链路，只替换画面表现层并增加可选视觉意图。

## 4. 设计原则

1. **动作先于陈列。** 第一帧优先使用现有真人剃须素材，产品转台镜头后置。
2. **信息变化先于切镜数量。** 只有新动作、新位置或新证据出现时才切换或放大。
3. **一个画面一个主效果。** 同一时刻不叠加大标题、参数卡、放大镜和复杂转场。
4. **文字只强化画面。** 画面没有展示的结论，不通过花字补出来。
5. **统一模板参数。** 动画速度、颜色和安全区由模板管理，不在 300 份 JSON 中分别调节。
6. **旧数据可继续渲染。** 没有视觉元数据时回退到当前基础表现，不破坏既有任务。

## 5. 目标创意结构

目标转换版为 18 秒左右，使用现有素材重新编排：

| 时间 | 画面 | Remotion 增强 |
|---|---|---|
| 0.0–0.6s | 真人剃须画面停帧 | 两行 Hook；局部压暗；一次首屏冲击音 |
| 0.6–2.5s | 真实剃须动作 | 约 110% 局部裁切；完整保留刀路；电机音效同步 |
| 2.5–5.5s | 同一素材的不同时间段或裁切区域 | 刀网接触位置标注；安排一次 3–5 秒 re-hook |
| 5.5–8.0s | 刀头或转子特写 | 只出现一个经确认的参数卡 |
| 8.0–10.5s | 水洗画面 | `直接冲洗` 关键词与水流同步出现 |
| 10.5–12.5s | Type-C 画面 | 充电口局部放大和短标签 |
| 12.5–15.0s | 手持产品 | 回顾最多三个已展示卖点，不引入新承诺 |
| 15.0–18.0s | 产品或礼盒镜头 | 只回顾已展示结果并给出具体商品卡 CTA；一次收束提示音 |

实际帧数仍由 TTS 决定。目标文案在生成音频后应落在 17.5–18.5 秒；不得用粗暴加速语音强行压入时长。

## 6. 实验变量隔离

“当前 23.189 秒文案”与“目标 18 秒文案”不是同一个实验：

1. 第一轮做视觉 A/B：保持当前文案、TTS、素材集合和 23.189 秒总时长不变，只比较旧视觉包装与新视觉包装。
2. 第二轮才测试 18 秒转换版：使用经过压缩的单主张文案，并与第一轮胜出的视觉包装组合。

这样可以避免把文案缩短、素材重排和视觉动效同时变化后，无法判断提升来自哪个因素。

## 7. 视觉系统

### 7.1 字体与颜色

- 中文字体：`PingFang SC, Microsoft YaHei, sans-serif`。当前 Mac 渲染环境必须确认 `PingFang SC` 可用；不可用时在预检阶段报错，避免静默更换字体造成版式漂移。
- 正文：`#FFFFFF`。
- 问题或风险词：`#FFD84D`。
- 已由画面展示的结果词：`#57E389`。
- 背景遮罩：局部黑色透明渐变，不再给所有字幕使用厚重整块底框。
- CTA 可使用抖音商品卡相容的红色点缀，但红色不参与普通卖点强调。

### 7.2 抖音安全区

1080×1920 成片中，关键文字默认限制在：

- 横向：72–880 px；
- 纵向：160–1390 px；
- 底部约 450 px 不放核心结论，预留给平台文案、音乐信息和商品卡；
- 右侧约 200 px 不放必须阅读的长文案，避开互动按钮列。

安全区作为调试覆盖层参与联系表检查，但不进入正式成片。

### 7.3 动效语法

- Hook 进入：5–8 帧，轻微缩放和位移，无明显弹跳。
- 关键词强调：最大放大至约 106%，随后立即回到 100%。
- 视频推近：单镜头总变化 3%–8%，不持续摇摆。
- 转场：主要使用硬切；全片最多一次 4–6 帧遮罩转场。
- 局部标注：一条细线、一个圆形标记或一次局部放大三选一。
- 每个画面只允许一个主要动效。

## 8. 最小组件架构

现有 `ProductionVideo` 继续作为唯一 Composition 组件和时间线编排器。表现层只增加三个职责：

### 8.1 `ShotLayer`

替代 `ProductionVideo` 中直接渲染的 `OffthreadVideo` 包装，负责：

- 现有 `fit`、`focusX`、`focusY`；
- 角色预设的缓慢推近；
- Hook 停帧和局部压暗；
- Proof 镜头的局部裁切；
- 保留现有句末 5 帧 Freeze 行为。

`ShotLayer` 不负责字幕、卖点文本或声音。

### 8.2 `OverlayLayer`

一个组件内部按视觉角色选择少量固定变体：

- `hook`：两行标题；
- `proof`：刀路或局部位置标注；
- `feature`：单个事实标签；
- `cta`：商品卡行动引导。

不为四种变体创建插件系统、注册表或动态配置引擎。

### 8.3 升级现有 `SubtitleLayer`

- 将整句按标点和长度切成 7–12 个汉字的短语。
- 短语时间按有效字符数量在对应 `voiceFrames` 内分配。
- 每次只显示一个短语，并允许一个强调词使用角色颜色。
- 所有计算为确定性纯函数，输入相同即可得到相同帧范围。

第一版不引入强制对齐模型。若真实投放证明按字符分配产生明显口型或重音错位，再单独评估语音对齐能力。

## 9. 数据契约

现有句子增加一个可选 `visual` 对象：

```ts
type VisualIntent = {
  role: "hook" | "proof" | "feature" | "cta";
  emphasis?: string;
  label?: string;
  sfx?: "impact" | "motor" | "water" | "usb" | "cta";
};
```

示例：

```json
{
  "id": "s02",
  "text": "五刀头刮得很干净。",
  "ttsText": "五刀头刮得很干净。",
  "visual": {
    "role": "proof",
    "emphasis": "五刀头",
    "label": "贴面刀路",
    "sfx": "motor"
  },
  "shot": {
    "sourceId": "existing-shave-source",
    "sourceInSeconds": 0,
    "sourceOutSeconds": 3,
    "fit": "cover",
    "focusX": 0.5,
    "focusY": 0.46
  }
}
```

设计约束：

- `visual` 缺失时使用旧字幕和基础镜头表现。
- `emphasis` 必须是 `text` 或 `label` 的子串。
- `label` 必须为非空短文本，使用 `Array.from(label).length` 计算时最多 18 个 Unicode 字符。
- `sfx` 只能引用模板内允许的音效枚举，不能接受任意网络地址。
- 动画时长、颜色、字号和安全区不得进入每条任务的 Props。
- 不新增视觉 schema 版本；这是对现有 v1 的可选、向后兼容扩展。

## 10. 数据流

```text
文案 + SMB 既有素材选择
  → 生产计划补充 visual 意图
  → TTS 生成 voiceFrames
  → buildProductionProps 校验并保留 visual
  → ProductionVideo 按句创建 Sequence
  → ShotLayer 渲染视频
  → OverlayLayer 渲染视觉意图
  → SubtitleLayer 计算短语字幕
  → BGM/SFX/TTS 混音
  → Remotion 一次编码
  → ffprobe、音频检测、联系表和人工 QC
```

## 11. 声音设计

### 11.1 固定资产

首版使用一条无歌词、节奏克制、已确认商用权限的科技感 BGM，以及至多五个短音效：

- Hook 冲击；
- 电机；
- 刀路标记；
- 冲水；
- Type-C 插线或 CTA 收束。

音频文件保存到生产公开目录，并在来源清单中记录作者、来源链接、许可证和取得日期。未能确认权限的音频不得进入模板。

### 11.2 混音

- TTS 仍是主声道。
- 有人声时，BGM 音量包络降低约 5 dB。
- 同一时刻只允许一个强调音效，避免抢占口播。
- 最终音频峰值目标不高于约 -1 dBFS；QC 同时记录整体响度，防止平台二次压缩产生失真。
- 当前代理素材没有音轨，因此视频元素继续静音，不尝试从代理中恢复不存在的声音。

## 12. 错误处理与回退

- `visual` 中存在未知字段、非法角色或非法音效时，在生成 Props 前失败。
- `emphasis` 不存在于文字中时失败，不静默取消强调。
- 字幕切分后规范化拼接必须等于原字幕；帧范围必须连续、无重叠且位于对应语音区间。
- 明确请求的 BGM 或音效文件缺失时，在渲染前失败。
- 没有 `visual` 的旧任务继续使用旧表现，不因视觉升级失败。
- 指定字体不存在时，首版生产预检失败并给出字体名，不使用不可控系统回退。
- 任何视觉层越过安全区不会自动缩成难以阅读的小字；应由联系表检查阻止交付。

## 13. 验证方案

### 13.1 自动检查

- `visual` 契约合法性和旧数据兼容测试；
- 字幕短语切分的文本守恒、连续帧、单帧边界和短句测试；
- Remotion 包 TypeScript 检查；
- 一条完整母版渲染；
- ffprobe 校验 1080×1920、30 fps、H.264、AAC 和预期时长；
- 音频峰值与整体响度检查；
- 关键帧联系表：约 0.3、1.5、3.5、8.5、11.0、14.0 和 17.0 秒。

### 13.2 人工检查

1. 首 3 秒静音观看仍能理解产品、动作和观看理由。
2. 25% 缩放预览时 Hook、字幕和 CTA 可读。
3. 所有关键文字位于抖音安全区。
4. 局部标注准确指向刀网、充电口或冲水位置。
5. 音效逐帧对应动作，不盖过 TTS。
6. 视频不存在伪造结果或画面无法证明的结论。
7. 与当前版本并排观看时，新版信息层级更明确，但仍像抖音原生内容。

## 14. 投放验证

第一轮仅比较视觉包装：

- A：当前 23.189 秒版本；
- B：同文案、同 TTS、同素材集合的新视觉版本。

优先观察 3 秒或有效播放率，其次观察 25%/50%/75% 留存、完播和商品点击率。展示量不足时不依据单次点击宣布胜出。

视觉版本胜出后，再测试 18 秒单主张文案。只有新模板和 18 秒结构都分别得到正向信号，才扩展到批量生产。

## 15. 非目标

- 不新增视频拍摄或 AI 生成画面；
- 不制作虚假前后对比；
- 不重写 TTS、素材代理或最终 QC 管线；
- 不建立任意可配置的动效平台；
- 不增加多套品牌主题；
- 不立即改造全部 300 条任务；
- 不把播放量单独作为成功标准。

## 16. 首版验收标准

1. 不带 `visual` 的现有 Props 仍能通过校验并保持当前渲染行为。
2. 带 `visual` 的 S5Max 母版可以完整渲染，且不增加运行时依赖。
3. 新版包含 Hook、Proof、Feature、CTA 四种视觉角色。
4. 字幕采用短语显示，文本不丢失、时间不越界、强调词正确。
5. 所有关键文字通过安全区联系表检查。
6. BGM、TTS 和音效均存在，音频峰值通过 QC。
7. 首 3 秒静音可理解，25% 缩放可读。
8. 只使用现有视频素材，所有新增音频具有可追溯授权记录。
9. 新旧 23.189 秒版本可以作为隔离变量的视觉 A/B 对照。
10. 未通过单条母版验收前，不进入批量渲染。
